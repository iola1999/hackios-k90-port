# 桌面翻页在 iOS 26 上没有动画：桌面只有一页（2026-10-28）

`gestures.py` 在 iOS 26 上量翻页时，600 ms 窗口内只出 1 帧，连一条帧间隔都凑不出来，swipe-right 因此打印不出数字；同一工具在 iOS 16.5 上给出 58.5／60.8 帧/秒。这里给出定性：触摸已经送到，桌面上只有一页，翻页那一步在测一个不存在的动作。

## 1. 触摸侧可以排除

`hackios-xnu-kernel/userland/src/rwtouch.c` 的 `SAMPLE_MS` 是 8，`drag()` 按 8 ms 一个采样把手指位置报上去，250 ms 的页翻手势因此有约 31 个 move 报告，频率 125 Hz，高于屏幕的 60 帧。手指轨迹从 x=0.85 走到 x=0.15，是屏幕宽度的 70%，远超一页的翻页阈值。

backboardd 侧的 HID 系统也起全了：`start HID system open...`、`HID system open ready in 0.0836073s`、`HID system start ready`、`HID system ready in 0.107264s`。同一份日志里 `IOHIDSessionFilterCreateWithClass Failed to initialize filter` 出现两次，对象是 `com.apple.HIDRMSessionFilter`，它没有拦住 HID 系统的启动，与翻页无关。

## 2. 桌面上只有一页

`bbmetal21` 的 `shot-01034`（t+100.6 秒，解锁后静止的桌面）里，图标网格只有三项：一个小组件、Photos、Settings。图标网格与 Dock 之间是 `Search` 胶囊，胶囊与 Dock 之间那段本应放页码圆点的区域是纯黑，没有圆点。`bbmetal25` 的最后一帧 `shot-04183` 是同样的布局，同一位置同样没有圆点。

iOS 在只有一页时不画页码圆点。两轮里都没有圆点，说明 SpringBoard 的图标模型里只有一页。一页的分页滚动视图上没有可翻的目标，手势带来的位移会被回弹吃掉。

## 3. 那一帧是什么

`bbmetal25` 的手势脚本每轮先拉控制中心、按 Home、从底部上滑，再做一次来回翻页。`shot-01350`（t+135.1 秒）拍到的是一帧过渡画面：`Photos` 与 `Settings` 的标签各出现两次、位置相差约 30 像素，小组件左侧多出两块黑色矩形。这一帧属于控制中心收起的过渡，与翻页无关。

`s01280`（t+128.1 秒）是控制中心本身，`s01415`（t+141.6 秒）回到桌面，两张的 md5 分别是 `ad55958b…` 与 `ae06bbbf…`；`s01385`（t+138.6 秒）与 `s01415` 的 md5 相同，也就是说 3 秒里画面一个字节都没变。这段时间正落在两次翻页手势之间。

## 4. 结论与 16.5 的差异

翻页这一项这三件事都不成立：手势没被识别（触摸报告足够）、动画被跳过（没有可动画的对象）、渲染侧不出帧（画面在 3 秒内完全静止）。

iOS 16.5 上量到的 58.5／60.8 帧/秒，说明那边有内容在动。两边的手势脚本与 `rwtouch` 的采样口径相同，差别在桌面内容：16.5 的桌面有没有第二页，这一轮没有记录，需要一轮对照才能判定。所以现在的结论只到「iOS 26 这边桌面只有一页，翻页手势没有可翻的目标」，16.5 的对照留给下一轮。

## 5. 下一步

先让桌面有第二页，再谈帧率。第二页可以用手势造出来，不需要改镜像：`rwtouch` 的 `drag X0 Y0 X1 Y1 MS HOLD [GRAB]` 支持先按住 700 ms 把图标拿起来，再拖到右边缘停住，iOS 会为拖到边缘的图标新建一页。要看那次手势是否成功，用截图里的页码圆点作为判据，比看图标位置稳。

造出第二页之后，翻页才是可测的动作，`gestures.py` 的 `swipe-right` 才会有数字。这一条同时是 goal 里「翻页内容可见且位置正确」的前提：一页的桌面上这一项无法验收。

`bbmetal21` 的 46.8 fps 与 `bbmetal25` 的帧率都不作为这一项的依据，按修订后的口径只引 `gestures.py` 那一行。
## 6. 作废的历史数字

`bbmetal17`～`bbmetal25` 里所有翻页帧率都不能当性能数据用：`bbmetal17` 的左翻 17.2、右翻 21.3，以及后面几轮同类位置的数字，测的都是桌面只有一页时的回弹，不是翻页。要引用翻页性能，先按 §5 造出第二页再把页码圆点作为判据。

iOS 16.5 侧的对照已经查过：`docs/progress/evidence/2026-10-25-codex-gpu-resume/kernel-queue-wait-s23-auto-default/run/sheet-1.png` 是 16.5 的桌面，图标网格 15 个应用加两个小组件、Dock 4 个，`ios165` 模板的 `/Applications` 只有 16 项，也就是一屏放完，同样没有第二页。所以 16.5 的 58.5／60.8 测的也是回弹。两边都有回弹的前提之下，16.5 的回弹出了完整动画、iOS 26 的回弹只出 1 帧，这是与页数无关的独立缺口。

## 7. 回弹动画那条缺口在 `bbm27` 消失

`bbm26` 上 `swipe-right` 是 `no animation to measure`，`bbm27` 变成 68 个间隔、32.2 帧/秒（p50 30.7 ms、p95 43.1 ms、最大 50.3 ms）。`bbm27` 与 `bbm26` 的唯一差别是把 `com.apple.mobile.installd` 补进了任务清单，所以「桌面只有一页时回弹不出帧」这条独立缺口在 installd 到位后消失。

翻页本身仍然不可测：`bbm27` 的截图里桌面还是一页、还是没有页码圆点，`swipe-right` 量到的仍然只是回弹。这两件事要分开记，不要把 32.2 帧/秒当成翻页性能。
