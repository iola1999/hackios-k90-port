| 串 | 来源 | 含义 |

## 3. 判据

### 3.1 缺页是不是成因

上一轮 `state` 段是 `wall 824045 cpu 128 flt 196`。若预落页有效，本轮 `flt` 应当接近 0，且 `state` 段的长尾消失。

| 观察 | 结论 |
| --- | --- |
| `flt` 接近 0 且 `fd draw seg slow` 的 `state` 条数降到个位数 | 缺页是成因，方向转到 device pager 的落页路径 |
| `flt` 接近 0 而 `state` 墙钟仍到几百毫秒 | 缺页排除，等待在别处 |
| `flt` 仍在一百到三百次 | 预落页没有覆盖到出问题的映射，先查它作用在哪个 BO 上 |

### 3.2 分段分布指向哪一处

| `state segs` 的分布 | 结论 |
| --- | --- |
| `cs_begin` 独大 | 时间在取环形缓冲的下一个 BO 与映射，配合 3.1 看缺页 |
| `emit_3d_state` 独大 | 时间在命令流写入，接着看它内部的状态对象构建 |
| 各段都小、`total` 大 | 落在没有埋点的语句上，按缺口位置继续拆 |

### 3.3 线程快照指向哪一类等待

用户态快照只给用户态 pc。线程睡在系统调用里时，pc 停在进入内核的 `svc` 之后。

| `stall` 行的 pc 落在 | 结论 |
| --- | --- |
| `libsystem_kernel` | 睡在系统调用，用 `tools/k90auto/stubsym.py` 解出调用名，再按名字分流（等锁、等信号量、等页、等 I/O） |
| 我们的库或 freedreno 的代码 | 在等锁或等页，看同一行里的 `lr` 与 `sp` |
| 内核地址段 | 不该出现在用户态快照里；出现说明快照取的不是用户态寄存器，判这次快照作废 |

### 3.4 采样有效性

`stall` 行只在慢 draw 存在时出现，而 `thread_get_state` 反映的是该线程上次被换出时的位置。慢 draw 那一轮若一条 `stall` 都没有，说明快照没有触发，不是「线程没睡」。判定采样有效的前提是同轮 `fd draw seg slow` 有非零条数。

## 4. 不允许的推断

- 不能把 `fd_perf_us` 的读数当真实微秒用；换算已经修好（`* numer / denom / 1000`），但历史轮次的数一律按 52.083 倍折算后引用。
- 不能用 `driver … max` 与 `rwa draw call` 的 `wall` 直接比大小，两者来自不同线程。
- 不能用一轮的 `prog_builds` 为 0 推出「不存在着色器编译」，只能推出该轮没有编译。
