# round fixguard 归档说明（骨架，修复轮）

回答[运行协议](../plan/k90auto-run-protocol.md) §5 要求的六项「这一轮跑的是什么」：内核、驱动、AIR 库、作业集合、手势脚本、探针版本。证据目录 `docs/progress/evidence/k90auto/kernel-12377-attr26-fixguard/`（轮名由 device 定 label `fixguard`，lead 没有另给名字），payload `out/handoff-12377-attr26-fixguard.bin`。本文件由 desktop 抄录维护，数据来源是 device 的打包回报与收尾回报，desktop 按文末复算命令独立复算核对。与 round F 的唯一差别是 AIR 库：round F 的 AIR 源码加一个 patch `hackios-xnu-kernel/tools/mesa/freedreno-shared-no-shadow.patch`（display，工作区 7,197 B，在 `fd_try_shadow_resource` 入口拒绝 shadow 一个 `is_shared` 的资源；它的说明段含 memmove 归属已定四项、三个行长的映射与「行长是被 map 的 box 的行长」的细化，`diff --git` 之前、`patch(1)` 会跳过、不进树），perf 已重建 AIR（`1be6ebf7…`、14,000,400 B）、device 重打 root 与 payload（AIR 库在 root 镜像的 `/lib/libredwoodair.dylib`，root.apfs 与 payload 的 sha 都是新值），第一次 fixguard 的唯一变量是这个 patch。第一次的两次启动尝试都死于 launchd 的守卫违规（根因已定，见 §2），**重跑按 lead 裁定加启动参数 `ool_port_array_enforced=0`**——重跑轮对 round F 记成**两个输入差异**（守卫 patch 与这个 boot-arg），boot-arg 的作用范围是「让 launchd 不在 OOL port array 策略上退出」，与三项成功判据无交集；不重建内核、不碰 overlay、不碰 `tools/mesa/`，root `a8e3c755…` 与 AIR `1be6ebf7…` 都不变，只有 cmdline 与 payload 哈希变（重跑条件、归还后顺序与偏离清单条目见 device 的[冻结形态分析](../analysis/2026-10-28-roundc-freeze-form.md)）。device 打包前有两条强制核验；liveness-watch.sh（`9c31aee`）加 nohup 执行方式是本轮硬门槛（round F 第二次异常的对策）；手册 §5 两条恢复规程（先抢拉环再 stop、每 60 s 核 `commands.jsonl` mtime）本轮起生效。

## 2. 判据（预先登记，lead 定、device 转发原文照抄）与本轮结果

- 重跑判别项（lead 10-28 晚定，排在三项成功判据之前——判「这一轮有没有效」的第一道分岔，比原版加一层）：**第一层**：重跑若仍死于 `exit reason namespace 23`，先看 AST 行的 `flavor` 是不是仍是 `0x43`——同一个 flavor 说明 boot-arg 没生效（名字写错或没传进去），不同 flavor 说明是另一条 guard 策略；这一层先判，它决定后面查什么。**第二层**：不再死于 namespace 23，才进三项成功判据。原文「同一个 namespace 23 再现即非偶发，需要去解 subcode 并找那个受保护的 fd」作废——flavor 已解到底（见下根因段），fd 支与本次失败无关。
- 总判据原文：「判据我预先写下来：bad access 归零就是故障修掉了，接着看形态是否从循环变成冻结或更好；bad access 不变就是守卫无效，C1 与 C2 两个候选排除，那时上 display 那四处打印，候选从四个减到两个。」

- AST 行与字段分解（分解已完成；不是从 subcode 反解的——AST 行直接打出了三个未打包字段，与按编码宏从 code 算出的值逐位相同）：fixguard `s001.log` 第 2194 行、fixguard2 第 2197 行、bbmetal11-panic 第 2178 行，三份一致，原文：

```
ERROR: [launchd.ios:1] EXC_GUARD AST: type=0x1 flavor=0x43 target=0x800407 code=0x2000004300800407 subcode=0x300000000000011
```
