# iOS 26 QEMU 启动与显示适配（2026-10-26）

本轮接续[会话交接](../plan/2026-10-26-session-handoff.md)，目标仍是先在 QEMU 中以软件渲染进入 SpringBoard。系统为 iOS 26.6.2（`23G90`），身份 `iPhone18,3`／`V57AP`，内核 `xnu-12377.121.6`。截至 `q26-input26-formal`，QEMU 已显示锁屏，正式独立输入服务通过 Home 按键进入 SpringBoard 并打开控制中心。当前启动依赖针对 23G90 的本地启动状态适配；多数图标、标签、组件内容与壁纸仍有显示缺失，翻页和控制中心的显示正确性正在验证。本轮尚未运行 K90 内核；只读查询确认驻留 loader v7 为 `idle`。

内核仓以 `fadb3a2` 加工作区修改构建，内嵌用户态仓库以 `31f5925` 加工作区修改构建。QEMU 参数为 `QEMU_CPU=neoverse-n2`、`QEMU_RAM_GB=14`、`MEMSIZE=300000000`、`IDENTITY=v57`；镜像分别为 `userland/root26.apfs`、`userland/system26.apfs`，内核来自 `out/xnu12377/BUILD/obj/DEVELOPMENT_ARM64_BCM2837/mach.development.bcm2837`。基础启动参数为 `serial=3 rootdev=md0 launchd_unsecure_cache=1`；launchd 诊断使用 `launchd_log_serial=1`，长时间运行使用 `0`，各轮参数另存 manifest。当前 QEMU framebuffer 为 1125×2436，尚未调整为 iPhone 17 的像素尺寸。

## 2. 日志与 XPC 握手

`OS_ACTIVITY_DT_MODE=YES` 在 23G90 上还要求 AMFI 返回 `AMFI_DYLD_OUTPUT_ALLOW_DEVELOPMENT_VARS`（bit 8）。旧 `kern_minimac.c` 返回 `0xff`，修改为 `0x1ff` 后，lsd 与容器服务的定向日志开始输出。标志定义见苹果 [DyldProcessConfig.cpp](https://github.com/apple-oss-distributions/dyld/blob/main/dyld/DyldProcessConfig.cpp)；实际消费分支已核对本地 23G90 的 `libsystem_trace`。`launchd_log_serial=1` 单独控制 launchd 的控制台日志。

容器查询先收到 `Bogus check-in attempt. Ignoring.`，随后 lsd 返回 `XPC_INTERRUPTED_REPLY`（52）并中止。23G90 libxpc 在 check-in 中调用 `mach_port_is_connection_for_service`，接受返回码 0 或 20；当前内核没有闭源 Sandbox 的消息过滤回调，原有前置检查返回 `KERN_NOT_SUPPORTED`（46）。临时内核日志确认实际经过该分支。

修复把回调检查移到非空 Sandbox 标签分支、增加引用之前。参数、服务端口接收权及类型检查保留；没有 Sandbox 标签的服务进入原有成功分支，返回 `filter_policy_id=0`。非空标签缺少回调仍返回 46，并释放局部 label 锁及端口锁。NULL-label 路径对 connection port 只检查名称有效性，这一范围沿用上游原有实现。

补丁保存为 `hackios-xnu-kernel/xnu26/patches/72-osfmk%ipc%mach_port.c.patch`，已加入 `series`。端口探针覆盖 NULL／DEAD 名称、已销毁名称、普通 receive port 冒充服务端口、只有 send right 的服务端口，以及真实 service／connection 的 `policy_id=0`；构造和清理也计入 19 项检查。带真实 Sandbox 标签的路径尚未运行验证。

## 3. persona 与用户容器

lsd 的中止来自 CoreServices 用户容器查询：class 10，persona 字符串 `com.apple.containermanager.primary-persona`，flags `0x900000001`。无法取得 URL 后，`0x18178738c` 调用 `abort()`。XPC 修复后，容器服务报告 UserManagement 返回空清单，进而返回 `INVALID_PERSONA`（76）。

只读探针确认内核已有 UID 501 的 system persona（type 4、ID 100）和 default persona（type 6、ID 200）。`persona.kb` 仍为 133 字节，`UserPersonaDictionary` 为空。内核 persona 和 UserManagement 返回的属性清单分别检查，不能仅从其中一项推断另一项已准备完成。

临时 arm64e 注入库仅在 `containermanagerd` 与 `containermanagerd_system` 内替换 `+[MCMUserIdentityCache personasAreSupported]`。23G90 方法地址为 `0x1e300e954` 加 shared cache slide，入口字节也在替换前核对。返回 `NO` 后，容器服务使用默认 personal identity 与 POSIX 用户；该配置只适用于当前单用户启动实验，不提供 persona 之间的容器隔离。XPC 修复与该配置共同启用后，90 秒内 lsd 没有再次中止。

UserManagement 的清单更新使用 `renamex_np(..., RENAME_SWAP)`，仅在目标不存在（`ENOENT`）时回退到普通 rename。`q26-sbdiag` 的独立探针确认 ramfs 对已有目标返回 `ENOTSUP`（45），文件内容与 inode 保持原值；普通 rename 和缺失目标回退均成功。新增 `ramfs_renamex` 在挂载锁内复查双方目录项并交换非目录节点，链接数及已打开文件描述符继续对应原节点；目录交换暂不支持。普通 rename 实现移入 `ramfs_rename.inc`。随后增加每 mount 的 `rm_rename_lock`，覆盖普通 rename 与 SWAP 的目录修改及 vnode 路径更新，防止驱动内部两次身份更新被另一轮交换交错覆盖；`vnode_update_identity` 仍在 `rm_lock` 外执行。`ramfs.c` 从 1998 行减至 1918 行，`.inc` 为 156 行。

`q26-sbthreads` 中 `tools/ramfs-rename-test.c` 的 19 项检查全部通过，覆盖同目录、跨目录、inode、打开的描述符、硬链接、符号链接、缺失目标、目录拒绝和普通替换。原始 133 字节 persona 清单由 usermanagerd 更新为 1439 字节，Personal ID 1000 与 Default ID 200 均与内核 UID 501 的 persona 对应。`q26-nativepersona` 撤掉容器服务临时替换后，lsd 继续注册系统扩展，未再次出现 `INVALID_PERSONA` 或容器 URL 引发的中止；临时替换已从默认构建中移除，实验源码保留在忽略目录。

`q26-rename-stress` 在 12377 上通过 19 项串行检查，以及同目录／跨目录、相反方向／相同方向四种并发模式；每种 128 轮、每轮两个线程各尝试交换 32 次，共 32,768 次并发交换尝试。32,767 次成功，跨目录相反方向出现 1 次 `ENOENT`，其余错误为 0。驱动会在目录项复查发现名称已对应其他节点时返回 `ENOENT`。每轮线程停止修改后核对 `F_GETPATH` 对应 inode、目录项和打开文件的内容，均通过，无超时或持续错误。XNU 在 VNOP 返回后还有基于名称／父目录指针的补充身份更新，ramfs 锁未覆盖该上游范围；本轮测试没有复现该范围的 ABA 问题。该次 `ENOENT` 的具体返回层未追踪。主机 APFS 上的独立烟测曾出现测试进程无法退出，已停止主机并发测试，该结果未用于判断 ramfs。

## 4. 显示初始化与帧结构

backboardd 已经过 HID 初始化、窗口服务器创建、容器缓存目录查询及显示枚举，报告 1125×2436、scale 3。随后 QuartzCore 创建 SILManager，需要 ExclaveOS 的指示器资源及 `com.apple.backboardd.SILManager` Conclave 服务；当前镜像缺少这些资源，创建失败后中止。

23G90 QuartzCore 已有 `com.apple.coreanimation` 域的 `CAEnableMedina` 布尔偏好。为 mobile 写入 `false` 后，显示对象跳过 SIL 状态创建，后续调用接受空 SIL 对象。`q26-nomedina` 已验证该配置消除本轮 SILManager 中止并开始提交帧；安全指示器服务尚未实现。

23G90 的 selector 5 请求长度为 `0x588`，驱动实际消费的字段相对 20F66 均增加 `0x48`：swap ID、四层 surface ID、source rect、enabled、destination rect、set／clear 掩码。`MiniFramebufferSwap.h` 严格接受 `0x46c` 和 `0x588`，新版从偏移 `0x48` 提供原有队列所需数据；复制截止于 `0x4b4`，位于请求范围内。后续协议字段不参与当前绘制。旧版请求保留原指针与内容，未知长度返回参数错误。

`tools/test-fb-swap.py` 用两版用户态写入位置分别构造输入，检查四层字段、未对齐地址、复制边界、NULL 和不支持的长度。ASan／UBSan 通过；删除新版偏移或放宽长度判断的对照均导致测试失败。新增头文件负责请求布局选择，原驱动从 1623 行减至 1615 行，队列与绘制流程保持原结构。

IOSurface 按 selector 13 的输出长度选择协议：20F66 为 `0x18`、版本字段位于 `+0x16`，23G90 为 `0x28`、版本字段位于 `+0x22`。新协议的结果头从 `0x68` 增至 `0x88`，plane 从 `0x80` 增至 `0x98`；驱动保留已有内部结构，在返回用户态前写入对应布局。共享页的 seed、use count 与锁状态保持原位置，bulk attachments 和 YCbCr 字段按协商版本访问。

每个 user client 只协商一次协议，surface 在首次成功映射后固定共享页布局，拒绝跨协议映射。共享数据仍只有一份，释放与引用计数继续由原有对象管理。失败路径补充 external pixel map 和新建引用的清理；释放统计在解除引用前保存大小。`MiniIOSurfaceABI.h` 与 `.inc` 分别保存布局和 user-client 方法，原 cpp 从 1814 行减至 1739 行。`tools/test-iosurface-abi.py` 的 ASan／UBSan 检查覆盖两版布局、初始化、映射、释放和失败清理，错误偏移及边界放宽的对照均触发失败。

`q26-surface` 已显示苹果启动标志，但 backboardd 的 libxpc 代码要求检查触发 `matched == (match_result.error_code == AICMR_MATCH)` 断言。AMFI 请求 `0x66` 的返回结构用 `error_code=0` 表示匹配，旧实现返回不支持并保留预先清零的结果，引发两者不一致。MiniAMFI 现先写入非匹配结果，再校验参数和读取约束数据，成功后按已有不强制执行策略返回匹配；约束语义仍未解析。`tools/test-miniamfi.py` 覆盖有效请求、无效长度、地址错误和读取失败，并保留原请求的回归检查。`q26-amfi66` 持续到约 166 秒，backboardd 已进入 Data Migration，画面显示进度条。

`q26-amfi66` 停留在 Data Migration。新建数据卷的模板仍记录 `20F66`；iOS 26 构建现从所选系统的 `SystemVersion.plist` 读取 `ProductBuildVersion`，更新生成模板中的 `LastSystemVersion` 与 `DMLastMigrationResults.buildVersion`。源码模板保留 16.5 值。`init` 先创建 RAM 数据卷，再由 `restore_var()` 覆盖已有保存记录，持久化数据原有迁移状态保持有效。`q26-migration` 确认 Data Migration 在 0.187478 秒内通过；SpringBoard PID 30 完成 check-in 后产生 corpse，PID 56 重启并再次完成 check-in，具体退出原因继续检查。

## 5. 构建与复现

在内核仓目录执行；SDK、静态 init／stage0 产物与 macOS 命令兼容环境沿用[交接记录](../plan/2026-10-26-session-handoff.md#4-构建与运行macos-主机)。QEMU 脚本在 macOS 上直接使用 `gtimeout`，内核计划返回后给 loader 预留 180 秒输出日志；此前 40 秒的上限曾截断详细日志。当前常规构建命令：

```sh
IOS=../ios26 PREBUILT=1 OSLOG=com.apple.backboardd userland/build.sh
XNU26_SRC=$PWD/out/xnu12377 xnu26/build-macos.sh -j16 -Otarget
```

`IOS=../ios26` 默认仅给 SpringBoard 加载 `libredwood-sb26.dylib`，同时加入独立的 `com.redwood.input26` 任务，生成 `CAEnableMedina=false` 偏好及所选系统构建号的迁移记录；可通过 `INJECT` 显式替换注入清单。16.5 的默认注入清单保持原样。`PREBUILT=1` 要求 `userland/obj/` 已有 `input26-service` 和 `libredwood-sb26.dylib`；构建会检查输入服务的签名及 HID entitlement。

运行参数见第 1 节。需要调查 launchd 时启用 `launchd_log_serial=1`，常规显示验证使用 `0` 并只给 backboardd 开启 `OSLOG`，以控制返回日志长度。`systrace=1 systrace_name=backboardd` 可用于失败的系统调用及异常检查；launchd 的 `exited with exit reason` 仍需单独检查，`userabort` 没有出现不能用于排除进程退出。
