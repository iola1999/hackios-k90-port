# GPU 加速目标（新版）：目标、授权与协作方式（2026-10-24）

本文按最新协作方式改写现有 goal，作为后续协作与验收的依据。技术目标、系统版本取舍、存储授权和性能验收要求沿用上版口径；本次更新集中在协作分工、验收与结果标注、技术长期原则。本文不解除当前实验暂停，push 与 flash 沿用现有授权。

## 1. 技术目标与完成判据

在 REDMI K90（SM8750／Adreno A830）的 HackiOS 工作区推进图形加速，直到真机完成 GPU 命令执行、shader 渲染，并接入 iOS 用户态图形路径，验证应用或桌面实际使用 GPU 绘制。最终完成要求保持：真机硬件渲染及用户态接入可复现，真实负载性能验收通过，关键故障恢复流程得到验证；记录源码提交、固件与产物哈希、操作步骤、性能对比及剩余限制。完成由主 agent 审查各阶段验收结论后判定；只有最终功能与真机性能验收通过后，整体目标才标记完成。

技术推进顺序沿用：从现有 GPU 暂停交接恢复，先核实仓库、产物和设备实际状态，保留已知可用启动产物；对照厂商实现确认 QTEE shmbridge 与安全内存调用约定，推进 kind 5 安全资源分配、START ACK、GPU 地址空间与命令执行，再完成 shader 渲染、像素读回及用户态接入。当前阻塞、各阶段准入与实施分级见[安全翻译方案](../analysis/2026-10-25-secure-translation-plan.md)与[交接计划](2026-10-24-gpu-handoff.md)。

## 2. 系统版本取舍（沿用上版）

系统版本不限，优先选择能够完成目标、兼容成本较低的版本；条件相近时优先较新版本，不以系统升级作为独立目标。保留 iOS 16.5 作为已有验证环境，按需要评估 iPadOS 17.7.11 或更新的版本；候选评估与选择条件见[交接计划](2026-10-24-gpu-handoff.md)§2。

## 3. 无人值守与存储授权（范围不变）

- 用户离开期间自主推进，普通实现细节不请求确认。允许按操作手册进行运行期 SCM/HFI 调用及 GPU 实验，接受实验可能需要后续物理恢复；禁止改写安全相关持久分区，不扩大其他未授权的持久写入。
- 系统盘优先通过 USB 传入 RAM。较高版本 iOS 确需更多持久存储时，允许按需扩大 userdata 中供本项目使用的写入空间、无需再次询问；执行前必须核实分区布局、文件系统占用及已有暂存区，确定写入范围、容量需求、备份和恢复办法，检查与 Android 数据及文件系统元数据的冲突。授权包含的范围到写入空间为止：任意覆盖现有用户数据、整分区格式化、未经验证的分区表修改都在授权之外。无法确认安全写入范围或恢复条件时暂缓该项，继续其他任务；记录实际写入范围和用途。两层并列：上一条是长期存储授权；当前实验不自动放行，主机 RAM 加载仍须审核镜像内部持久副作用，超出授权范围要另行确认；新的 userdata 持久写即使有上一条授权，也单独裁决后执行。
- 授权不自动扩展：新发现的重大持久化或跨启动风险（例如移交后物理页归属跨复位未知）要先说明并取得对超出原授权部分的确认，再执行对应操作。
- 实验前明确超时和有限的软件恢复策略；按规定执行 GPU 实验收尾冷重启，PSCI 重启后的重新枚举与身份、状态检查只能确认恢复可达，复位后的归属验收按 §7。设备失联且软件恢复失败时，暂停依赖真机的任务，记录需要用户完成的最少恢复操作，继续源码分析、实现、主机测试、构建、用户态接口和系统版本兼容性研究。同一失败实验不反复执行；离线完成后真机结果仍无法验证的，如实保留未完成状态。

## 4. 角色与路由

- 主 agent：架构决策、任务拆分、对重点报告的高风险结论做原文抽查、重大风险审查与完成判断。主 agent 上下文不承担重研究与大范围审查，需要细节时读指定文件的指定段落。
- Qwen3.8-Flash-Next 子 agent：在明确范围内负责实现、测试、构建、设备操作与文档。
- 复杂架构、协议问题、独立风险审查与验收：优先固定 GPT-6.1-Sol，路由实际允许时使用；不可用时改用固定 Astra。已创建的 agent 保持模型不变、按 ID 复用，可按需并行多个；创建前先检查路由，创建失败按实际结果汇报，不声称已启动。

## 5. 验收与结果标注

- 验收优先由未参与对应实现的 agent 执行；报告需经主 agent 审阅，高风险结论核对原文、关键 diff 与原始日志后决定是否通过。
- 报告分别标注执行者（实现者/独立验收者）、验证环境（主机/真机）、结果与未验证范围；各维度分别记录。
- 构建来源强制：固定 commit、clean 展开、文件哈希、产物与 payload 绑定；构建记录缺一则产物不得用于真机结论。测试切片要写明覆盖边界（代码路径、场景、环境）。
- 已交付报告或文档发现错误时，先修正对应文档再继续依赖它的步骤。

## 6. 执行与并行

- 保留一个持续执行的 agent，按需要增加调研、验收 agent；任务派发时写明范围、交付内容、成功条件、失败处理，减少重复阅读。
- 并行有边界：并行任务持有独占文件与独占输出；同一设备与共享构建产物由单一执行者串行操作，实施与验收任务之间明确移交设备使用权。
- 等待结果不轮询、不重复发确认消息，完成由执行事件送达；主 agent 只在方向变化、发现风险或收到求助时干预。复杂问题先对齐方案、取舍与准入条件再派发。

## 7. 技术长期原则

- 安全移交、安全翻译、START、GPU 执行、shader、桌面合成逐级验收，一级通过支持不了下一级；初始化成功、mock 成功、单次 scratch 写回只计入对应阶段。
- 对固件零回复只限制新增地址发布，现有消费者停止缺少保证；PSCI 复位后重新枚举只验收恢复可达性，跨复位的物理页归属与 WAITQ 请求取消未知，相关风险单列审批。
- host 超时与 stop 标志取消不了已在执行的 SMC 调用；loader 生命周期状态未确认时，禁止复用其运行内存，并禁止可能冲突且未经安全确认的 IRQ、UFS、充电等接管、恢复与写操作；经安全审查的 USB 日志读取、状态查询和复位入口保留可用。
- 推进顺序先修保护、主机独立验收、固定版本构建、只读诊断，移交实验另行审查放行。
- 阶段计划按当前验收标准书写，临时 commit 与实验性限制记录为带生效条件的内容，不写成永久目标。
- 准入门槛用可核实前提加明确裁决的未知风险；不要求公开接口无法提供的绝对证明（例如证明所有 SID2 消费者停止、所有固件保留已知）。各阶段准入细则写在专门方案文档。

## 8. 性能验收（沿用上版）

- 按阶段验证：安全资源分配和 START ACK；GPU 命令写回正确且无新增 SMMU fault；真实 shader 执行与像素读回符合预期；iOS 用户态实际使用硬件渲染，完成 IOSurface 合成及故障恢复验证。
- 必须完成真实设备上的性能验证：先保存现有软件绘制环境的可复现基线，再测硬件加速路径；尽量保持场景、分辨率、系统配置、供电和温度一致，记录无法消除的差异。覆盖离屏渲染与真实应用或桌面交互，测量帧时间及其分布、卡顿、CPU 占用，测量手段可靠时记录输入到显示延迟、GPU 活动及频率。关键测试重复执行，保留原始结果、测量方法与异常情况。
- 验收要核实实际渲染路径，检查软件回退、画面错误、同步问题、内存故障及持续运行中的性能退化。无法直接测量的指标明确标注，主观流畅度和理论数值替代设备测量的不采纳。性能目标由主 agent 根据基线与测量条件在对应优化实验前确定；未达目标时继续定位原因或说明限制。

## 10. 与上一版的差异

- 协作：主 agent 审阅范围明确为高风险结论原文抽查、关键 diff 与原始日志；复杂架构、协议、独立风险与验收给出路由顺序（GPT-6.1-Sol 优先，不可用时改用 Astra）与已创建 agent 复用规则；新增派发准入（先方案与准入再派）、并行边界与等待规则。

- 技术：新增 §7 长期原则与授权不自动扩展条款；技术目标、OS 取舍、存储授权、性能验收正文沿用。
