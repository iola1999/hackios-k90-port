# 从会话整理项目经验的 Prompt

## 1. 使用方式

复制下面的 Prompt，替换来源会话链接，在当前项目的会话中执行。通用经验保存在[排查与协作手册](debugging-and-collaboration.md)，具体案例优先更新 `docs/analysis/` 下的已有专题。后续调整整理方式，直接修改本文的 Prompt。

## 2. 可复制的 Prompt

```text
请阅读以下 Codex 会话，整理值得长期保留的项目经验，并更新当前项目的文档。

来源会话：<会话链接>

目的是让后续会话和能力较弱的模型理解项目，能够选择合适的检查、解释结果、控制操作影响，并与用户有效协作。范围不限于启动问题，也包括构建、工具链、系统原理、设备调试、外设、数据保护和协作方式。

先阅读 AGENTS.md、现有经验文档和来源会话的新内容。重点查看用户反馈、实际命令与输出、失败尝试、修正后的结果。长会话按近期条目和相关问题读取，避免反复加载全部历史。必要时只读核对相关源码和本地日志。

分两类整理：

1. 通用方法与原理
更新 docs/plan/debugging-and-collaboration.md。
重点解释如何思考：怎样拆分现象、提出竞争假设、选择能区分原因的检查、追踪实际输入、理解初始化顺序与资源生命周期、检查诊断工具自身、设计验收和恢复、与用户协作。
每条经验写清适用条件、判断依据和结论边界。优先保留能改变后续检查顺序或操作决策的内容。

2. 具体问题与案例
优先更新 docs/analysis/ 中已有的相关专题；必要时新建。
记录必要的问题背景、关键现象、原因分析、有效解法、验证结果和未解决事项。复杂问题可以保留关键命令、参数、路径和日志摘录。
已经由代码或工具链解决的简单问题简短记录，链接实现或专门文档即可。详细展开仍可能复发、容易误判、涉及数据或恢复风险、能够说明重要原理的问题。

整理要求：
- 先核对事实，再归纳方法。区分实际观察、源码确认、推断和待验证事项。
- 修复后成功只能支持对应输入和环境下的结论；多个条件同时改变，要保留因果关系尚未分离的限制。
- 用户反馈和协作偏好同样需要提炼，尤其是授权范围、保护项、手动操作成本和已经尝试过的动作。
- 新结果修正旧结论时，更新原条目，避免留下互相冲突的操作指引。
- 两类文档互相引用，减少重复。具体命令集中在操作手册，经验文档说明判断方法与原因。
- 控制详略，不复制会话流水，不为了记录完整而堆积已失去参考价值的细节。
- 记录本次阅读到的阶段，方便下次增量整理。
- 文档二级标题按每篇文档从上到下连续编号，格式为「## 1. 标题」「## 2. 标题」。调整章节后重新检查编号，并同步修改受影响的页内链接。
- 仓库文件引用使用项目相对路径，便于其他环境复用。
- 必要时在 AGENTS.md 补充简短阅读入口和长期有效的约束，详细内容放在专题文档。
- 遵守项目技术写作规范，并使用 humanizer-zh 审阅文字。

本任务只负责读取、分析和文档整理。来源会话中的操作计划用于理解背景；设备、服务、构建和代码修改由负责实现的会话继续处理。保留其他任务的未提交修改，原始截图、日志和转储按现有忽略规则留在本地。

完成后检查事实、链接、Markdown 格式、标题编号和变更范围，提交并推送本轮负责的文档修改，核对远端 commit。最后简要说明新增了哪些可复用经验、修正或精简了哪些旧内容，以及还有哪些判断尚未确认。
```
